# IT固定资产管理系统

一个轻量级的企业IT设备固定资产管理系统，适用于医院、公司等组织。

## 功能模块

- **IT设备档案管理**：设备录入、编辑、归档，自动生成资产编号
- **手机设备管理**：手机设备档案管理
- **医疗设备管理**：医疗设备档案管理
- **电话号码管理**：运营商、主副卡、使用人、状态（注销/不再使用）
- **微信账号管理**：微信账号、密码、实名人、使用人、用途
- **设备流转管理**：领用、归还、部门调拨、离职回收，自动更新设备状态
- **报废管理**：报废申请、审批、归档，通过后设备自动标记为已报废
- **删除审批**：所有删除需走审批流程，管理员/超级管理员审批
- **部门管理**：部门档案，设备按部门归类
- **用户权限**：仅超级管理员按用户配置操作权限和部门范围；角色名称在创建或编辑用户时填写，不关联权限
- **用户表格导入**：超级管理员在用户权限页下载模板，批量新增普通用户（每批最多100人）。表格可填写初始密码、邮箱、角色名称、已有部门、数据范围及独立权限；任意行出错则整批不写入，已有账号不覆盖。权限留空表示无操作权限，超级管理员账号通过页面手动创建。
- **医疗校准管理**：医疗设备支持可选的校准时间与校准到期时间，列表显示校准剩余天数；工作台和医疗模块可选择用户发送30天内校准到期及逾期邮件，与设备使用期限到期提醒分别处理。仅填写的校准到期时间参与提醒，已报废或已移出档案的设备排除。模板、导入和导出支持两个日期，旧模板“校准到期”列仍兼容；到期时间不得早于校准时间。邮件通过页面手动选择收件人发送，不自动批量发信。
- **报表统计**：设备台账、部门统计、闲置清单，支持导出Excel
- **操作日志**：记录关键业务操作
- **数据库备份**：启动时备份，超级管理员也可手动备份和下载

## 技术栈

- **后端**：Python FastAPI + SQLite
- **前端**：Vue 3 + Vite
- **桌面客户端**：Electron（免安装版）
- **部署**：Windows 服务器 + Caddy HTTPS 域名入口；后端仅监听本机

## 快速启动

### 后端
```bash
set IT_ASSET_SECRET_KEY=请设置高强度随机密钥
set IT_ASSET_BOOTSTRAP_PASSWORD=首次部署时的管理员密码
pip install -r backend/requirements.txt
cd backend
python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

`IT_ASSET_SECRET_KEY` 是必填项。只有数据库尚无用户时才需要
`IT_ASSET_BOOTSTRAP_PASSWORD`，首次管理员创建完成后应删除该环境变量。

### 前端开发
```bash
cd frontend
npm ci
npm run dev
```

### 构建桌面客户端
```bash
npm run electron:build
# 打包入口读取 dist/index.html；默认连接 https://slzz.cloud
```

## 权限与流程升级说明

- 独立角色权限模块已移除。普通用户的权限仅来自超级管理员的逐项分配，修改角色名称不会改变权限。旧用户已保存的权限保留；尚未单独保存的历史角色权限在首次升级启动时固化到用户，之后与旧角色模板脱离。账号身份中的“超级管理员”与普通角色名称分别配置。
- 部门管理、全局日志和微信管理属于全局权限，必须配置全部部门范围。微信密码权限依赖微信管理；模块导入/导出还需该模块权限。报表导出需要报表和导出权限。
- 数据范围支持“查看全部，编辑本部门”：允许读取全部部门的资产和统计，新增、编辑、导入及其他业务写入仍仅限所属部门。后端先检查原记录归属再合并编辑字段，防止修改部门绕过限制。管理员可在用户权限页或导入模板选择此范围；必须填写所属部门。其他模块仍按独立操作权限访问。
- 登录令牌包含用户身份与会话版本；改密码或停用会使旧登录失效。本次升级后所有用户需重新登录一次。
- 申请、审批、流转历史使用部门和用户 ID 关联。启动时执行一次可重复运行的增量结构升级；历史姓名只有唯一匹配时才补齐身份。重名或缺失记录仍保留原始信息，需要管理员核对。
- SQLite 业务写入先取得写入锁再读取状态；审批与直接流转共享状态规则。审批重新核对资产最新状态，重复审批不会重复执行。
- 资产编号使用持久递增序列，新增和导入共用；删除中间记录不会导致编号重复。资产删除审批通过后移出活动档案，保留原记录供历史关联；有历史记录的用户应停用，有关联数据的部门不能直接删除。
- 流转记录保存资产类型/ID、原使用人、原部门、新使用人、新部门和操作人。已有记录缺失的去向无法凭空恢复。
- Excel 导入限制上传10MB、解压50MB、10000条数据、100列；解析和保存由工作线程执行，日期/数字格式错误返回行级提示。
- 备份使用实际运行数据库路径。上线前停服务并保留数据库及代码备份，部署代码和前端构建产物后启动服务，再检查迁移和登录。回滚时使用配套备份；数据库、备份及密钥不要提交 Git。

## 隔离回归测试

从仓库根目录运行，测试会创建临时数据库和临时备份目录，不连接生产服务：

```bash
python -m pip install -r requirements-dev.txt
ruff check backend maintenance
ruff format --check backend maintenance
python -m unittest discover -s backend/tests -v
cd frontend
npm run format:check
npm test
npm run build
```

后端覆盖权限模板、跨部门/自我/并发审批、报废状态、编号、部门改名、同名用户、密码会话、报表范围和导入限制；前端逻辑测试覆盖申请字段映射、报表独立加载及导出、导入导出按钮权限。前端逻辑测试不替代浏览器验收。

## 运行性能

- 模块导出与汇总报表仅查询需要的列，每批读取 500 行，使用只写工作簿；输出超过 1 MiB 自动转入临时文件，下载按 64 KiB 分块，并在结束时关闭文件。原有表头、日期、部门范围和密码排除规则保留。
- 工作台接口并行加载，单个接口失败仍展示其余结果；统计逐次累加，到期提醒只保留需要显示的前 10 条。
- 账号状态仍每 15 秒刷新；后台标签页暂停轮询，切回时立即刷新，慢请求不会重复叠加。权限仍由后端逐请求校验。
- 发送提醒邮件不再提前占用 SQLite 写锁，邮件等待期间可以保存其他业务。审批等业务写入仍使用原有串行校验。
- 隔离测试覆盖慢邮件期间的写入、导出文本与日期，以及并行加载、到期排序和轮询清理；测试不会发送真实邮件。

## 维护和代码规范

- 当前发布入口及只读数据库检查见 [维护说明](maintenance/README.md)。旧目录、旧 ngrok、无保护清库及全进程重启脚本已退出发行。
- Python 使用 Ruff，前端使用 Prettier；前端统一 npm 11.6.2 和 package-lock.json，不混用 pnpm 锁文件。格式化命令为 `ruff format backend maintenance` 及前端 `npm run format`。GitHub Checks 工作流执行静态检查、回归测试和生产构建。
- 独立角色权限管理已删除，但旧角色表、历史迁移、旧接口的明确退役响应仍保留，保障历史升级兼容。
- 资产更新只覆盖明确提交的字段；未提交字段保留，明确传空值才清空可选字段。编号不能清空，普通流转不允许直接执行报废。
- 登录密码验证在写锁外执行，发放登录令牌前再次核对账号状态和会话版本。单账号每分钟最多10次、单来源最多30次登录尝试，超过返回429并可在一分钟后重试；当前限流针对单进程部署。
- 前端共享响应式用户状态，权限刷新请求合并；退出后迟到的响应不会恢复旧账号。
- Excel 输出会在导出副本中移除 XML 不支持的控制字符，原数据库资料不变；构建失败也清理临时工作表文件。
